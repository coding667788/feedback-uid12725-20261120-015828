开发一个本地值守裁定器，将两类合成告警合并为可复核的事件，并计算每个事件的双人复核期限。环境 Windows 原生 Python 3.12、标准库，可用 SQLite。只处理虚构告警和排班，无网络、无真实告警或外部服务。交付 import-batch、seal、review、report、verify 命令。

每条告警带通道、站点、安全区域、整数分钟、类型和来源事件 ID。规则表由输入声明允许关联的类型对和最大时间差。建立跨通道候选边，要求同站点同区域且类型对和时差均合规。事件以一个候选连通分量为边界，同时列出实际边证据；同通道告警只能经合法跨通道边间接归入同一事件。未获关联的单条告警也形成事件。窗口 watermark 由输入单调推进；只有分量最晚告警时间加上该规则表全局最大时间差严格小于 watermark 时才能封存，以免后到合法边串连。导入时事件时间严格小于当前 watermark 的新告警写入迟到档。精确重放已有事件保持幂等。封存事件 ID 由规则版本加排序后的源事件 ID 决定，封存回执保留使用的水位、分量边和原事件摘要。改变规则仅影响整轮新批次，禁止用新规则改写已封存事件。

从 seal 采用的 watermark 起，按该站点值守表累加 30 个覆盖分钟作为审核截止，只算至少两名不同组人员当班的去重分钟，不按人头重复累计。值守表用半开区间，允许跨日和重叠；无足够覆盖分钟则单列“无可排期限”。双签须绑定事件摘要，人员属于不同组，并在各自签发时当班；签发时间须大于等于封存水位且严格早于截止时刻。一次审查的两签可异步完成，互换提交顺序不影响结论；已记录的同内容签收幂等。排班更正须建立新版本，旧封存和审查结论永久绑定原版本。读取状态、签收和封存各使用一致快照。

交付 README、生成器和测试。覆盖通过第三条告警把两个暂存事件合并、与最大时差恰等的合法边、封存水位恰相等、迟到告警、空班和重叠班、截止分钟、异组与同组、批次中断后恢复。写独立小样本逐分钟参考核对期限。
